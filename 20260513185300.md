# Committing to `dotfiles`

The `dotfiles` alias in `.zshrc` is:

```sh
alias dotfiles='git --git-dir=$HOME/.dotfiles --work-tree=$HOME'
```

Use it anywhere you'd use `git`. The git dir is the bare repo at
`$HOME/.dotfiles`; the work tree is `$HOME`. Because the work tree is
pinned, the current directory doesn't matter — run `dotfiles` commands
from anywhere.

## Standard flow

```sh
dotfiles status                              # what's modified
dotfiles diff                                # review unstaged changes
dotfiles add <paths>                         # stage
dotfiles commit -m "<scope>: <summary>"      # commit
dotfiles push                                # push to GitHub
```

## Adding a new file to tracking

The first time you track a path, force-add past the implicit ignore on
`$HOME`:

```sh
dotfiles add -f ~/.config/newapp/config.toml
```

Subsequent `dotfiles add` on the same path works without `-f`.

## Commit message style

Scope-prefixed, imperative mood. Recent examples:

- `mango: replace swww+theme-switch with ornatus`
- `zsh: add ~/.local/bin to PATH`
- `nvim: enable harper_ls for markdown`

## Cloning on a new machine

```sh
git clone --bare https://github.com/ppitchford/dotfiles $HOME/.dotfiles
dotfiles checkout
```

If checkout complains about existing files in `$HOME`, back them up or
remove them first.
